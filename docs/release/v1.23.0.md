# v1.23.0 - Verification Three Times Faster by Starting Fewer Processes

Date: 2026-11-19

## What changed

### Why it was slow

- Measured on Windows (6 cores, 12 threads): the forced suite took 458-479 seconds, and 333 of them
  were the `pro-roundtrip` group. One test file there started 12,609 child processes (12,608 of them Git); its main thread
  spent 187 of 199 busy seconds inside `child_process.spawn`, and 86% of the calls repeated an earlier
  one. The test logic itself cost nothing.
- Process creation is serialized system-wide on that machine: 6, 11 and 20 test workers took 171, 168
  and 171 seconds. So the suite is as slow as the number of processes it starts, and more workers do
  not help.

### Fewer Git processes in the Pro roundtrip (the real command gets faster too)

- A blob was read with four processes (`rev-parse`, `cat-file -t`, `cat-file -s`, `cat-file blob`).
  `readGitObjects` now reads object id, type and bytes with one `git cat-file --batch` call, and a flow
  snapshot reads everything below the flow directory with one listing and one batch call.
- The six pinned protocol files are read with one call, and their history with one
  `git log --full-history` call when that proves the per-file answer: that list contains every
  per-file history, and a file present at the ref has at least one entry, so a single commit with all
  six files present means each per-file history is exactly that commit.
- The snapshot derives its directory listings from the one listing when every path uses characters Git
  prints unquoted, and the operator-close check asks for the history first (no history means absent).
- Every fast path returns only what the previous per-file commands would return. Anything else, and
  every error, still goes through those commands, so messages and fail-closed behavior are unchanged.
- The protocol history calls pass `--no-follow`. With `git config log.follow true` a one-path
  `git log` also lists the commits of byte-identical copies, so v1.22.0 rejected a second protocol
  generation under that setting ("immutable protocol file has 2 history entries"). History is now
  counted per path whatever the setting.
- One flow test went from 2,279 Git processes and 107 seconds to 456 and 26; the group from 333 to 78
  seconds. A real `vibe-pro-go` command starts about a fifth of the processes it did.

### One runner for consecutive test groups

- `verify` ran each test group in its own `node --test` process, one after another, so a group waited
  for the slowest file of the group before it. Consecutive test groups now run in one runner
  (`node:test` `run()`), and each failed file is attributed to the groups that own it.
- Unchanged: one execution per group per run, receipts and their input hashes, the
  `[vibe-verify] start group=` lines, `verification group failed: <id>` and the input-stability check. A
  receipt's `durationMs` is now the duration of the pooled run that verified the group. When an earlier
  group fails, a later group that passed in the same run now keeps its receipt.

### Tests

- The Pro CLI suite is one module (`pro-roundtrip-cli-suite.ts`) run by four test processes, and the two
  tests that prepare several independent repositories prepare them side by side.
- `statusline.sh` only starts `statusline.mjs`, so four tests keep what the wrapper adds (it runs the
  script, passes stdin and bytes through, exits 0). Six rendering cases run on `statusline.mjs`
  directly, and one case that repeated an existing test word for word is gone.
- Three new tests pin the guards of the batched reads (a directory where a blob is required, a protocol
  file with no history, pinned content that differs while the worktree copy matches). Each fails on a
  seeded bug the previous suite did not catch, and each passes on the v1.22.0 source. A fourth covers
  the `log.follow` case above.

### Launchers and walks

- Nine npm scripts start TypeScript with `node --import tsx` instead of `npx tsx`: about 600 ms less per
  call. The `git add` / `git commit` config-audit hook goes from 1,077 to 464 ms with its wiring
  unchanged.
- `vibe-context-audit` walked the whole repository, including ignored build and scratch directories, to
  resolve glob references. It now walks only the directory before a reference's first wildcard: 9.3 to
  0.5 seconds on a 195,598-file checkout, with byte-identical output. Its walk also no longer spreads a
  directory's files into one call, which overflowed the stack on that checkout.

### Fixes found on the way

- The dashboard's port discovery skipped a port in use (`EADDRINUSE`) but failed on a port the system
  refused (`EACCES`), which other processes can cause on Windows. It now tries the next port for both.
- `claude-fable-5-2` is registered with the Astra profile, and the statusline warns about
  `VIBE_ACTIVE_MODEL` only when the claimed and the reported model select different profiles: harness
  commands behave the same for two models of one profile.

## Downstream impact

- Sync updates `.vibe/harness/**`, `.claude/statusline.mjs`, `.vibe/model-registry.json`, three docs and
  the nine `vibe:*` script bodies in `package.json`. Hook wiring in `.claude/settings.json` is unchanged.
- A project that edited `.claude/statusline.mjs`, `vibe-context-audit.mjs` or the model registry locally
  for the two fixes above now matches upstream.
- No migration, schema, protocol or dependency change. Requires Node 24, as before.

## Verification

- Forced suite, same machine: 479, 467 and 458 seconds before; 139, 142, 156, 170 and 167 after (five
  consecutive green runs).
- The 647 tests of v1.22.0, unmodified, on the new code: one failure, the statusline test whose meaning
  this release changes on purpose.
- Thirteen seeded bugs (the removed, moved and rewritten statusline cases, the pooled attribution, the
  port skip and six in the batched reads) each fail a test.
- Old and new protocol verification agree on 23 histories with default Git settings, including merges
  that reach a file's history from one parent only (the two that differ need `log.follow=true`, above); statusline output is identical on 48 inputs; the nine script launchers
  give the same exit codes and output; context-audit output is identical on two checkouts.
- Full forced release verification, nine groups: legacy 651 tests, 650 pass, 1 skip, 0 fail; Astra 643
  tests, 641 pass, 2 skips, 0 fail. Build, tracked wrapper, shard, sprint-mode, sync and config audits
  passed.
- Size: harness source +304 lines net and tests +131, above the +150 guideline for one iteration; the
  measured friction is the justification.
