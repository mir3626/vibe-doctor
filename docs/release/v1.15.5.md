# v1.15.5 - Bounded Review Inputs and Missing-Event Diagnostics

Date: 2026-09-22

The review helper previously printed the entire handoff and session log even when
`review.recentEntries` was set. Long-running projects could therefore inject more
than a megabyte of historical state into a review. Default stdout is now bounded
to 64 KiB of UTF-8 JSON, including metadata. It omits the full session log, limits
the handoff prefix and recent complete entries, and reports source references,
original/returned byte sizes, truncation and omitted array counts.

Oversized entries are omitted whole so that a partial event cannot retain LIVE
while losing its terminal status. Omitted content has not been reviewed: use the
referenced sources to read only the relevant line ranges before drawing a
conclusion. JSON escaping and Unicode boundaries count toward the output budget.
The final serialized response is checked before writing; no unbounded fallback is
used. `collectReviewInputs` still returns full source text to programmatic
consumers, and `detectOptInGaps` runs on the original inputs before projection.

Active dated headings and bullets without a separating space now produce
`sessionLogFormatWarnings` with 1-based source lines. These diagnostics reveal
records that the recent-entry reader may miss; they do not parse arbitrary
Markdown as events or infer execution status. Archived sections and fenced
examples are excluded from warnings. Existing entry ordering and source records
remain unchanged. The review protocol explains targeted retrieval and writing a
new `- <full ISO timestamp with timezone> [tag] text` record that references the
historical block instead of rewriting it.

CLI JSON consumers must use `inputs.recentSessionEntries` and `output.fields`
rather than expecting `inputs.sessionLog`. Consumers requiring the original
collection can continue using the library API. Downstream upgrades should use the
normal sync dry-run and preserve local review/opt-in detector customizations.
No product migration, model call, goal-state transition or downstream upgrade is
performed by this release.

Regression coverage exercises actual CLI subprocess output, large logs and
collections, escaped Unicode, whole-entry omissions, terminal records, preserved
opt-in decisions and unchanged raw collection. Release verification uses the full,
forced harness command, including Pro Git/worktree integration.

Versioned release validation: all nine forced Astra groups passed, with 590 tests
(588 passed, two conditional platform skips, zero failures), including all 59 Pro
integration tests. Build, generated-schema consistency, sync boundaries and
tracked-wrapper audits also passed.
