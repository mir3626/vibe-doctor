# v1.19.0 - Converged Sync Files, Model-Switch Warning and Stagehand 4.2.1

Date: 2026-10-13

A second downstream project (osint-stock-screener) carried the Claude Opus 5.5 Astra change locally
and asked upstream three questions in its handoff. This release answers them and fixes the JSON
output of `vibe:sync`.

## What changed

- **Converged files are not conflicts.** `buildSyncPlan` used to report every harness file whose
  local hash differed from the recorded one, even when the local bytes already equal the new upstream
  file (a downstream patch that upstream has since released). Such a file is now a `replace` with
  reason `local copy already matches upstream`, with or without sync history. Files that still differ
  remain conflicts. Byte comparison is exact, so line-ending differences still conflict.
- **Model-switch warning.** Harness commands judge the profile from `VIBE_ACTIVE_PROVIDER` /
  `VIBE_ACTIVE_MODEL` only; after `/model` they keep the old model's profile. The statusline, which
  receives the model Claude Code reports, now adds `⚠️ VIBE_ACTIVE_MODEL <declared> ≠ <reported>`
  while the two disagree (a context-window suffix such as `[1m]` counts as the same model). The
  profile guide documents the limit.
- **Unregistered strong Claude models.** The profile guide states that a model such as
  `claude-fable-5-1` stays legacy until a same-condition comparison registers it, and CLAUDE.md's
  legacy-model override gate now says that capability tier and harness profile are separate.
- **Stagehand 4.2.1.** The template devDependency moves from `^4.1.0` to `^4.2.1` (published
  2026-10-11; same `node >=22.18.0` engine). Only the Stagehand package changes in the lockfile.
- **`vibe:sync --json` stdout.** The clone and backup log lines no longer precede or follow the JSON
  plan on stdout in JSON mode, matching the existing guard on the floating-range notice.

## Downstream impact

- Projects that applied an upstream change by hand before its release see fewer sync conflicts.
- The statusline may show the new warning if a project's `.claude/settings.local.json` `env` names a
  model other than the running one; update or clear the variables.
- `devDependencies` are project-owned, so sync does not bump Stagehand downstream. Projects run
  `npm install -D @browserbasehq/stagehand@^4.2.1` themselves and check with `npm run vibe:test-ui`.
- No migration, schema, or protocol change.

## Verification

Release validation (2026-10-13, Windows 11, Node 24.14.1) ran after staging every release file: forced
`vibe:verify:release` passed all nine groups without session model variables (626 tests, 625 passed,
one conditional platform skip, zero failures) and in a Claude Opus 5.5 Astra session (618 tests, 616
passed, two conditional skips, zero failures). `npm run vibe:test-ui` passed both real-Chrome Stagehand
4.2.1 tests.
