# v1.17.1 - zod 4 Error-Message Assertion Hotfix

Date: 2026-09-22

v1.17.0 shipped with the full forced verification skipped, and its CI `verify` and `astra` jobs
failed on one test: the Pro roundtrip CLI alignment-brief gate case asserted the zod 3 issue
message `"message": "Required"` for a missing `classification` enum key, while zod 4 reports the
same condition as code `invalid_value` with the message `Invalid option: expected one of ...`.

## What changed

- `pro-roundtrip-cli.test.ts` now checks the issue path (`classification`) and accepts either
  issue code (`invalid_type` on zod 3, `invalid_value` on zod 4), so the same harness test suite
  passes on a zod 3.25 root (downstream projects that have not migrated yet) and on zod 4.
- No runtime, schema, migration, or protocol change. Version metadata moves to 1.17.1.

## Downstream impact

- Downstream projects on v1.17.0 keep working; syncing 1.17.1 replaces one test file so the harness
  suite stays green after the project's own zod 4 migration.

## Verification

Full forced `vibe:verify` on the final tree (recorded below), the single reproduced test under zod 4,
and remote CI on the published commit.

Release validation (2026-09-22, Windows 11, Node 24.14.1, root zod 4.6.5): forced `vibe:verify` passed
all nine groups with 622 tests (621 passed, one conditional platform skip, zero failures); the
reproduced Pro roundtrip CLI case passes under zod 4.
