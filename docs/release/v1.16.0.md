# v1.16.0 - Stagehand Replaces Playwright for Harness Browser Automation

Date: 2026-09-22

The harness browser layer now runs on [Stagehand](https://github.com/browserbase/stagehand)
v4 (`@browserbasehq/stagehand`) instead of `@playwright/test`. Stagehand drives the Google
Chrome that is already installed on the machine over CDP, so there is no browser download
step, and the deterministic harness paths attach without a model: no LLM API key and no
Browserbase account are needed for `npm run vibe:test-ui` or `npm run vibe:browser-smoke`.
The natural-language `act` / `observe` / `extract` primitives remain opt-in for product tests.

## What changed

- `npm run vibe:test-ui` (`test:ui`) runs `.vibe/harness/scripts/vibe-stagehand-test.mjs`,
  which executes `.vibe/harness/test/stagehand/*.test.ts` with `node --import tsx --test`.
  Stagehand ships no test runner, so the wrapper owns the former Playwright config defaults:
  test directory, serial execution, pass-through `--test-*` flags, `--list`, exit-code and
  signal propagation, and install guidance (package plus Chrome / `CHROME_PATH`) when the
  dependency is missing. The dashboard and project-report scenarios are unchanged in intent
  and now assert through `page.waitForSelector`, `page.evaluate`, and a polling helper.
- `vibe:browser-smoke` keeps its `smoke.config.js` contract (`url`, `viewport`, `expectDom`,
  `expectConsoleFree`, `sleep`/`delayMs` warnings, `disabled` output, exit 2 install guidance)
  and gains an optional `timeoutMs`, an HTTP >= 400 main-document failure, and a `PASS`
  summary line. Its runner is exported with an injectable launcher, so the goto / selector /
  console / status paths are unit-tested without Chrome. Console issues are read from the
  raw CDP `Runtime.consoleAPICalled` payload Stagehand exposes.
- Shared helpers live in `.vibe/harness/scripts/lib/stagehand-browser.mjs`: install
  detection (the package does not export its `package.json`), guidance text, headless page
  lifecycle (`localBrowser.launch` + `Stagehand.create` without a model, `logging: off`),
  console-event normalization, Chrome-not-found hints, and `waitForCondition`.
- Test-pattern shard: `ts-playwright` / `typescript-playwright.md` is replaced by
  `ts-stagehand` / `typescript-stagehand.md`, covering install, a `node:test` example with
  deterministic locators, opt-in `act` / `observe` / `extract` with a model, the missing
  Playwright APIs (`getBy*`, `expect`, `locator.waitFor`, `filter`), and determinism notes.
  The interview answer-parser allowlist, the pattern index, and the canvas isolation shard
  follow the rename.
- Permissions and CI: the `npx playwright` allow rules leave `.claude/settings.json` and the
  agent-delegation preset; `vibe:sprint-mode` treats them as retired rules and strips them
  from `settings.local.json`. The CI verify job no longer installs Playwright browsers and
  relies on the runner's system Chrome. `.gitignore` drops `playwright-report/`.
- Docs and rules: CLAUDE.md, README, orchestration, the Planner agent, the review checks,
  and the sandbox invariants in `_common-rules.md` now name Stagehand UI-test output where
  they named Playwright traces.

## Downstream impact

- Migration `1.16.0` (registered in `sync-manifest.json`) removes the retired harness files
  (`playwright.config.ts`, `vibe-playwright-test.mjs`, `test/playwright/`,
  `playwright-wrapper.test.ts`, `typescript-playwright.md`) only when they match the synced
  hash or a published release blob, writes `.vibe/harness-migration-1.16.0.md` for anything
  it keeps, rewrites `test:ui` / `vibe:test-ui` scripts that pointed at the old wrapper, and
  re-points the `VIBE:TEST-PATTERNS` marker block in `docs/context/conventions.md` to the
  Stagehand shard without touching text outside the markers. It never edits
  devDependencies or project-owned Playwright suites.
- After `vibe:sync`, install the new harness dependency:
  `npm uninstall @playwright/test && npm install -D @browserbasehq/stagehand`. Keep
  `@playwright/test` only if the product has its own Playwright suite. Local and CI runs need
  Google Chrome or Chromium; set `CHROME_PATH` when it is not auto-detected. Project-owned
  `settings.local.json` entries are cleaned by the next `vibe:sprint-mode on|off`.
- `isHarnessQaScript` still recognizes the retired wrapper path, so downstream QA keeps
  skipping harness UI scripts until the migration rewrites them.

## Verification

Regression coverage: wrapper install guidance / `--list` / `--help`, the smoke runner with a
fake page (networkidle navigation, selector waits, console capture, HTTP failure, missing
url), the contract warnings against the new shard, migration removal / retention / report /
script rewrite / conventions block / idempotence, and the manifest and QA filter updates.

Release validation (2026-09-22, Windows 11, Node 24.14.1, system Google Chrome): forced
`vibe:verify` passed all nine groups with 618 tests (617 passed, one conditional platform
skip, zero failures), including the 59 Pro integration tests. Harness typecheck, build,
generated-schema check, sync/sprint-mode/shard/codex-wrapper/config audits passed. The real
Stagehand UI run (`npm run vibe:test-ui`) passed both scenarios in 12.8 s with screenshot
evidence, and the real browser smoke passed against a local fixture and failed as intended
on console errors, a missing selector, an HTTP 404, and an unreachable server, with no Chrome
processes left behind. Remote CI for this release is verified only when it runs after publication.
