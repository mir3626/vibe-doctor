# v1.21.0 - Speed-Quality Pace and an Owner-Facing Interview

Date: 2026-10-29

## What changed

- **Pace.** vibe-doctor helps non-developers, whose requests may want a quick MVP or a
  quality-first result. Every request now runs at speed, balanced or quality
  (`docs/context/orchestration.md` section 9). The request's own words decide first
  ("일단·MVP·프로토타입" or "제대로·출시용·완성도"), then the optional `.vibe/config.json`
  `pace` (absent or `auto` skips it), the reasoning effort the user set when it is known
  (low/medium: speed, max: quality), and the model profile (legacy: speed); otherwise
  balanced. The agent records `[decision][pace]` and a roadmap header line instead of
  asking, and follows a change the user makes.
  - Speed keeps the 3-5 Sprint MVP roadmap, detailed Planner handoffs and minimal changes.
  - Balanced sizes Sprints by user value and leaves methods to the Generator; open points
    are settled by the goal.
  - Quality also aims at the goal at its best and refines visible output after looking at it.
  - No pace changes explicit scope, file limits, verification or authorization. The rule
    lives in one place; CLAUDE.md `HARNESS:sprint-flow`, AGENTS.md, the sprint planner,
    the coder agent, `_common-rules.md`, `astra-rules.md`, the legacy delegation template
    and the vibe-init/vibe-iterate roadmap steps point to it.
- **Claude Opus 5.5 delegation routing.** The delegation template sent every Claude runtime
  to the legacy workflow, against `astra-rules.md`, the model registry and CLAUDE.md. Astra
  eligibility in the template and the 16 skill gates now names the Astra profile: GPT-6
  Astra, Claude Opus 5.5 (any context-window variant) or a registry successor.
- **Owner-facing interview.** The question synthesizer asks the owner only what the owner
  knows (users, situations, what they have, success, likes and refusals), decides expert
  and technical matters itself, and asks a consequence in plain words with a recommended
  option when the owner has to weigh it. "추천해줘 / 모름 / 알아서" on such a question records
  the recommendation (changeable later) instead of deferring; "나중에 정할게" still defers.
  Legal or regulatory gates ask only the deciding facts; wording, trademark and licensing
  checks are noted for the end. The bundle question explains itself and recommends
  `automatic`; browser smoke is decided from the platform.
- **Legacy delegation.** The "<500 LOC" Sprint target is gone (it contradicted the product
  quantity-cap rule). After two failed Sprints the agent diagnoses and chooses the technical
  fix (approach, stack) itself, and asks the user only outcome-changing choices such as
  reducing the spec; other ambiguity is settled by intent and recorded. The orchestration
  escalation path says the same.

## Downstream impact

- Sync updates harness-owned docs, skills and agents (`.claude/**`, `.codex/**`,
  `.vibe/agent/_common-rules.md`, `.vibe/agent/astra-rules.md`,
  `docs/context/orchestration.md`) and the CLAUDE.md `HARNESS:sprint-flow` and AGENTS.md
  `HARNESS:agent-memory` sections. Claude Opus 5.5 sessions that receive the delegation
  prompt now follow `astra-rules.md`.
- `pace` in `.vibe/config.json` is optional; the template does not set it, and absent means `auto`.
- No runtime migration, schema, protocol or dependency change. Project-specific harness
  customizations still require conflict review during sync; preserve local hybrid-file
  overrides, including hooks and document shards.
