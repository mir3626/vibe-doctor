# v1.18.0 - Claude Opus 5.5 Astra Profile and Downstream Dogfood Fixes

Date: 2026-10-13

This release brings back the general harness changes a downstream project (vibe-office) made after
syncing v1.17.1. Changes that still carry project values are tracked in
`docs/plans/downstream/vibe-office-queue.md` and are not part of this release.

## What changed

- **Claude Opus 5.5 uses the Astra profile.** `resolveHarnessProfile` resolves per provider family
  (`claude` is an alias of `anthropic`). An Anthropic model is eligible only through a registry entry
  marked `harnessProfile: astra`; a context-window suffix such as `[1m]` names the same model; Claude
  4.x and earlier, Sonnet and Haiku are known lower tiers that a registry entry cannot promote. The
  registry's `anthropic.opus` is now `claude-opus-5-5` with `harnessProfile: astra`. CLAUDE.md,
  `astra-rules.md` and the profile guide name both eligible models. A Claude session declares itself
  with `VIBE_ACTIVE_PROVIDER=anthropic` and `VIBE_ACTIVE_MODEL`.
- **Astra state contract.** `astra-rules.md` defines the restart state (the overwritten current-state
  section at the top of `handoff.md` plus the project's queue documents, one-line session-log
  pointers) and marks `sprint-status.json`, `iteration-history.json` and pendingRisks as legacy-only.
  It adds a one-line new-session suggestion for large unrelated work on a half-full context, records
  user corrections in the repository's rulebook, and states that it overrides CLAUDE.md mechanical
  overrides 1-2. `re-incarnation.md` follows.
- **PreCompact no longer edits tracked state.** `vibe-checkpoint.mjs --auto-refresh` writes the git
  snapshot to git-ignored `.vibe/runs/precompact-snapshot.md` instead of splicing it into `handoff.md`
  and bumping `handoff.updatedAt`. Every compaction used to dirty two tracked files and make the
  freshness check pass by itself. In hook mode a stale narrative is a `systemMessage` warning; only
  missing or corrupt state blocks compaction.
- **config-audit runs after `git add` / `git commit` only.** The PostToolUse hook matches `Bash` with
  handler `if` rules instead of every Edit/Write (one downstream project measured 5,663 runs with no
  violation). This needs a Claude Code release that supports the hook `if` field (verified on
  2.1.293); an older release runs the audit after every Bash call.
- **Statusline ⚠️ under Astra.** The statusline counted every open pendingRisk, so legacy advisories
  that no Astra workflow resolves stayed on screen forever. Under Astra it now counts only the open
  audit findings that preflight `audit.overdue` fails on, through a shared
  `classifyAstraAuditRisks`. It resolves the profile from the model Claude Code reports, falling back
  to the environment; the statusline tests run without the session's own model variables.
- **Verification runner test.** `verification-runner.test.ts` required the template's `scripts.test`
  value, which is a project key, so it failed in every downstream project with its own test script.
  It now checks that value only in the template.
- **vibe-init lite start.** A short-lived content or tool repository skips Phases 1-4 and copies
  three templates (`CLAUDE.template.md`, `RULEBOOK.md`, `.gitattributes`) from
  `.claude/skills/vibe-init/templates/lite/`. The Codex wrapper notes the exception.
- **Iteration carryover.** `iteration-history` entries accept an optional `carryover`
  (`backlogDoc`, `open`), and `vibe-iterate` phase 0 folds still-open items into the differential
  interview.
- **Harness gaps.** Five rows: precompact self-freshening and config-audit latency (covered), Astra
  state drift (partial), and Claude-session Windows text and silent hybrid-section overwrites on sync
  (open).

## Downstream impact

- Sync replaces the changed harness files. `.claude/settings.json` `hooks.PostToolUse` takes the new
  `Bash` + `if` handlers through the json merge. No migration is needed.
- A Claude Opus 5.5 session that should use Astra sets `VIBE_ACTIVE_PROVIDER=anthropic` and
  `VIBE_ACTIVE_MODEL=claude-opus-5-5` (for example in the git-ignored `.claude/settings.local.json`
  `env`). Without them, harness scripts keep the legacy profile; the statusline still sees the model
  Claude Code reports.
- Existing `iteration-history.json` files stay valid; `carryover` is optional.
- Sync still overwrites downstream edits inside CLAUDE.md harness sections and settings `hooks`
  without a conflict (`gap-sync-silent-hybrid-overwrite`). Diff those files after syncing.

## Verification

Release validation (2026-10-13, Windows 11): forced `vibe:verify:release` on the final tree passed all
nine groups twice. Without session model variables (as in CI): 624 tests, 623 passed, one conditional
platform skip, zero failures. In a Claude Opus 5.5 session (`VIBE_ACTIVE_PROVIDER=anthropic`,
`VIBE_ACTIVE_MODEL=claude-opus-5-5[1m]`, Astra): 616 tests, 614 passed, two conditional skips, zero
failures. The same changes ran downstream in vibe-office before this release.
