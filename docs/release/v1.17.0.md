# v1.17.0 - zod 4 Runtime, Nested Role-Table Preservation and Contiguous Session-Log Tags

Date: 2026-09-22

Three downstream findings from the vibe-office handoff plus the harness move to zod 4, folded
into one release after v1.16.0 (Stagehand) was published.

## What changed

- The harness runtime now depends on `zod@^4` at the root. `zod-to-json-schema` is removed;
  `vibe:gen-schemas` generates the 13 state and protocol schemas with zod's native
  `z.toJSONSchema` (draft-07, input side, inlined reuse) and keeps the previous
  `$ref` / `definitions` / `$schema` envelope. Regenerated schemas are semantically equivalent
  to the previous files: shared subschemas are inlined instead of `$ref`-linked, integer bounds
  and ISO date-time patterns are explicit, `additionalProperties: false` is no longer emitted
  because state files are parsed with strip semantics, and discriminated unions use `oneOf`.
  Source changes are limited to explicit `z.record(z.string(), ...)` key schemas and the
  `ZodType` base type. Stagehand's `extract()` schemas can now use the root `zod` import.
- `/vibe-sync` section-merge failed to preserve the CLAUDE.md role table. The marker written by
  `/vibe-init` carries a description (`<!-- BEGIN:SPRINT_ROLES (vibe-init 자동 업데이트 영역) -->`),
  which the exact-marker regex never matched, and the block sits inside `CHARTER`, an
  upstream-owned block that the merge replaced wholesale. The parser now accepts an optional
  description after the marker name on both `BEGIN` and `END`, section discovery recurses into
  block bodies, and a second pass re-applies every preserved local section (`preserveMarkers`
  and `PROJECT:*`) wherever the same-named block appears in the merged output. Harness and
  other upstream-owned sections still take the upstream text.
- `vibe-session-log-sync` captured only the first `[tag]` of an entry and treated the rest as
  body, so `[decision][sprint-roadmap-drafted]` was rewritten as `[decision] [sprint-roadmap-drafted]`
  and `vibe-init-ready` could no longer find the roadmap record. The normalizer now captures the
  whole leading tag cluster and canonicalizes it without whitespace, repairing previously spaced
  entries on the next run. The init-ready roadmap gate and the preflight planner-skip lookup also
  tolerate a space between tags for hand-edited logs.
- The template configuration shipped `harnessVersionInstalled: 1.8.3`, so the statusline and
  preflight reported a stale installed version and recommended a sync inside the template itself.
  v1.16.0 set it to the released version and the release process now keeps it aligned.

## Downstream impact

- Because the three Pro protocol schema files (`FLOW`, `CONTRACT`, `EVENT-COMPLETE`) changed
  bytes, the content-addressed protocol namespace derives a new `v1-<hash>` generation. Existing
  bridges bootstrap the new namespace under the normal `--publish` authorization; flows pinned to
  the previous generation are reported as superseded by `go`, as designed since v1.12.0.
- Downstream projects on zod 3 must upgrade their root dependency after `vibe:sync`:
  `npm install zod@^4` (and remove `zod-to-json-schema` if it was only used by the harness).
  Product code that still needs zod 3 APIs should migrate per the zod 4 changelog; the harness
  itself only requires `zod@^4`.
- Projects whose CLAUDE.md role table was overwritten by an earlier sync can restore it from the
  `PROJECT:custom-rules` copy or from git history; after this release the `SPRINT_ROLES` block is
  preserved on every sync regardless of nesting or marker description.
- Running `vibe-session-log-sync` once rewrites spaced tag clusters back to the contiguous form.
  No other entry text, ordering, deduplication or archived sections change.
- No harness migration script is required for this release.

## Verification

Regression coverage: schema drift check against the regenerated files, a semantic old-vs-new
schema comparison (0 differences after `$ref` resolution and known-equivalent normalizations),
schema/protocol/sidecar/model-registry parsing tests under zod 4, described and nested marker
preservation (SPRINT_ROLES inside CHARTER, PROJECT section inside a harness section, malformed
marker still returns null), contiguous and canonicalized session-log tags with a body that
contains brackets, and the existing init-ready, preflight, sync plan and session-log tests.

Release validation (2026-09-22, Windows 11, Node 24.14.1): the full forced `vibe:verify` was
skipped by user directive for this release. Checks that did run on the final tree: harness
typecheck, `vibe:gen-schemas -- --check` (no drift), the semantic old-vs-new schema comparison
(0 findings), focused schema / protocol / sidecar / model-registry / config tests (72 passed) and
sync / session-log / init-ready / sync-glob tests (60 passed), plus the sync, codex-wrapper,
sprint-mode, review-shard and config audits. The last full forced run on the sync/session-log
fixes alone (before the zod 4 change) passed 622 tests with one conditional skip.
