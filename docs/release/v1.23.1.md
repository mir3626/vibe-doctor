# v1.23.1 - The Former CLI Suite File Keeps Its Name

Date: 2026-11-19

## What changed

- v1.23.0 renamed `.vibe/harness/test/pro-roundtrip-cli.test.ts` to `pro-roundtrip-cli-suite.ts` and ran
  it through four new shard files. The sync planner never emits a delete action, so a downstream that
  synced v1.23.0 would keep the old file, and `verify` rejects a test file no group owns
  ("unowned root harness tests"). Every downstream would have failed its harness verification after
  that sync. Found before any downstream synced v1.23.0.
- `pro-roundtrip-cli.test.ts` now exists again as a three-line shard (the `close` part of the suite),
  so a sync replaces the old whole-suite file in place. The suite runs as five test processes; the
  `guards` shard of v1.23.0 is split into `close` and `guards`.
- `docs/context/harness-gaps.md` records the limitation as `gap-sync-retired-file` (open): retiring a
  harness file needs a migration that removes it, as `1.16.0.mjs` does, or the name has to stay.

## Downstream impact

- Sync from v1.22.0 or v1.23.0 with no manual step. From v1.22.0 the old CLI test file is replaced by
  the shard; from v1.23.0 one test file is added.
- Everything in `docs/release/v1.23.0.md` applies. Prefer this version over v1.23.0.

## Verification

- Full forced release verification, nine groups: legacy 651 tests, 650 pass, 1 skip, 0 fail; Astra 643
  tests, 641 pass, 2 skips, 0 fail. Build, tracked wrapper, shard, sprint-mode, sync and config audits
  passed.
- A dry-run sync from a v1.22.0 downstream lists `pro-roundtrip-cli.test.ts` as a replaced file.
