# v1.21.1 - Drop the Write() Deny Rules Claude Code Never Matches

Date: 2026-11-04

## What changed

- Claude Code now warns at startup about every `Write(path)` deny rule, for example
  `Deny rule Write(secrets/**) never matches · use Edit(secrets/**)`. `Edit(path)`
  rules cover every file-writing tool, so a `Write(path)` deny rule never blocks anything.
- The extended preset (`.vibe/settings-presets/agent-delegation-extended.json`) no longer
  lists `Write(.env*)`, `Write(secrets/**)` or `Write(config/credentials.json)`. Their
  `Edit(...)` twins were already there and still block writes to those paths, so
  protection is unchanged. `vibe-sprint-mode-audit` accepts either form.
- `vibe-sprint-mode` treats those three rules as legacy preset deny guards, the way it
  already treats legacy colon-form allow rules: `on` drops them from an existing
  `.claude/settings.local.json` before merging the preset, and `off` removes them along
  with the other preset rules. Custom `Write(...)` deny rules that the preset never
  shipped are left alone.
- Allow rules are unchanged; the `Write(docs/**)` allow rule and its `Edit(docs/**)`
  twin both remain.

## Downstream impact

- Sync updates the harness-owned preset and `vibe-sprint-mode.mjs`.
- A downstream `.claude/settings.local.json` keeps the three stale lines until
  `/vibe-sprint-mode on` or `off` runs once, or until they are deleted by hand. The
  warnings are harmless in the meantime.
- No runtime migration, schema, protocol or dependency change.
