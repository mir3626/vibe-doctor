# v1.20.0 - Deterministic PowerShell Runs

Date: 2026-10-13

Agents on Windows kept failing PowerShell calls in different ways on each try. Three things stack up
when code is passed inline (`powershell -Command "..."`):

1. The calling shell and PowerShell both parse the same string, so quotes, `$`, backticks and spaces
   are interpreted twice.
2. PowerShell reads typographic quotes (‘ ’ “ ”) as quotes and en/em dashes (– —) as `-`. Korean report
   text pasted into the code ends a string early or turns into an operator. `-EncodedCommand` only
   removes the outer shell layer and fails at the same place.
3. Windows PowerShell 5.1 reads a `.ps1` file without a BOM in the ANSI code page, so UTF-8 Korean and em
   dashes in the file become different characters (an em dash's bytes include `”` in cp1252).

The fix is to keep code and data apart. Data passed through arguments or environment variables reached
the script unchanged in every case tried; code written into a file and run with `-File` avoids the
double parse.

## What changed

- **`vibe-ps.mjs`** (`npm run vibe:ps -- ...`):
  - Runs `<file.ps1>` or `-c <code>`. Everything after the script is a positional argument.
  - Named parameters come from `--param Name=value` (`--param Name` alone passes a switch) or
    `--param-file Name=path` (the UTF-8 text of a file). Environment variables come from `--env NAME=value`.
  - `--shell auto|pwsh|powershell`: pwsh when it is on `PATH`, else Windows PowerShell 5.1.
  - `--check` parses and checks only. `--allow-typographic` turns the typographic check off.
- **ASCII-only bootstrap** (`scripts/lib/vibe-ps-bootstrap.ps1`, run with `-NoProfile -NonInteractive
  -ExecutionPolicy Bypass -File`):
  - Reads the call from environment variables as JSON and removes them before the script runs.
  - Reads the code as UTF-8 with or without a BOM, and parses it with PowerShell's own parser.
  - Runs the parsed script block under its file name, so `$PSScriptRoot` and `$PSCommandPath` are the
    script's own.
  - Sets UTF-8 console output, `$ErrorActionPreference = 'Stop'`, no progress records and (PowerShell
    7.2+) plain-text rendering.
- **Refused before anything runs (exit 65):**
  - Parse errors, each reported as `file:line:column: message`.
  - Typographic quotes outside comments and here-string bodies.
  - Typographic dashes outside comments and strings.
- **Exit codes:**
  - The script's own `exit N`, even inside `try`.
  - 1 when an error stops the script; the message and the script's position go to stderr.
  - 0 when the script ends. The exit code of a native command the script ran does not decide this.
  - 64 for a usage error, 127 when no PowerShell is found.
- **Rule.** The CLAUDE.md hook table and `_common-rules.md` tell agents to use the helper instead of
  inline PowerShell, with the data passed as arguments, parameters or environment variables. Gap
  `gap-powershell-inline-quoting` (no hook blocks an inline call).

## Downstream impact

- New harness files sync as harness-owned: `vibe-ps.mjs`, `lib/vibe-ps-bootstrap.ps1` and
  `vibe-ps.test.ts`. The `vibe:ps` npm script is also harness-owned.
- The CLAUDE.md hook-enforcement section gains one row. Projects that moved that table into a shard
  (for example `docs/context/hooks.md`) add the row there after the sync.
- Requires Windows PowerShell 5.1 or PowerShell 7. On Linux and macOS the helper uses `pwsh`, and exits
  with 127 when `pwsh` is not installed.
- No migration, schema, or protocol change.

## Verification

- `vibe-ps.test.ts`: 14 tests on Windows 11, run on both pwsh 7.6.6 and Windows PowerShell 5.1.22621.
  - Text with typographic quotes and dashes, Korean, `$`, a backtick and double quotes is passed as an
    argument, a parameter, a file parameter and an environment variable, and comes back unchanged.
  - A BOM-less UTF-8 script containing a Korean literal prints it correctly. `$PSScriptRoot` matches a
    Korean folder name that contains a space.
  - `exit 3` inside `try` ends with 3. `throw` and a missing file end with 1.
  - Typographic characters are reported at the exact line and column, and are allowed in comments,
    here-strings and strings. Parse errors give exit 65.
- The test also runs in the Windows CI job.
- Release validation (2026-10-13, Windows 11, Node 24) ran after staging every release file. Forced
  `vibe:verify:release` passed all nine groups in two runs:
  - Without session model variables: 640 tests, 639 passed, one conditional platform skip, zero failures.
  - In a Claude Opus 5.5 Astra session: 632 tests, 630 passed, two conditional skips, zero failures.
