# v1.15.3 - Current Review Evidence and Checkout-Safe Skills

Date: 2026-09-09

Review input collection now sorts active session entries by timestamp before
applying the recent-entry limit. It also reads timestamped entries in the legacy
preamble, preserves original lines and equal-time ordering, and excludes archived
sections. Legacy partial dates use UTC only as a sorting convention; undated
active entries follow dated records. No existing log is reordered or rewritten.
The maintain-context writer now explicitly adds new entries immediately below
the first `## Entries` heading, matching the Sprint writer.

The Codex wrapper audit adds opt-in `--tracked` mode. Every wrapper, shared
runbook and declared transitive shard must exist both locally and in the Git
index. Git failure is an error, not a working-tree fallback. The default mode
continues to support local/generated trees without Git. Both JSON and text
output identify the mode; upstream CI now requests tracked mode.

Run `npm run vibe:codex-wrapper-audit -- --tracked` before a release or checkout
parity check. Index membership does not attest that unstaged text was committed:
also verify the final clean checkout. Downstreams with custom CI should add the
flag to their existing wrapper audit and commit only required shared documents,
not entire ignored skill/config directories.

Use a sync dry-run and preserve local overrides. In particular, merge only the
review recency change when review.ts has downstream gap-classification logic.
No migration, new LLM stage, model change, Pro flow or product server execution
is introduced. A separate Lodestar R33 launch-path mistake is an operational
finding, not a Web Pro design or generic harness runtime defect; that product
quality goal remains stopped and is not resumed by this release.
