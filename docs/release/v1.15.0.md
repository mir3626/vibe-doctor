# v1.15.0 - Model-selected Workflows and Shared Runtime Correctness

Date: 2026-09-07

GPT-6 Astra can use a smaller execution contract while lower and unknown models
retain the established prompts and workflow obligations. Improvements to runtime
correctness and test infrastructure apply to every model.

## Astra workflow

- Only exact `gpt-6-astra` or explicitly verified successors registered with
  `harnessProfile: "astra"` qualify. An override cannot promote a lower model;
  ambiguous provider/configuration and unknown models remain on the legacy route.
- The short `.vibe/agent/astra-rules.md` contract replaces mandatory role splits,
  settled interviews, creative bets, per-file test quotas, cleanup commits,
  repeated QA ceremonies and unsupported heuristic authority.
- Native sessions select context on demand and retain a durable work queue,
  design decisions, handoff/session log, checkpoint and meaningful verification.
- Wrappers resolve their child model independently. Lower children never inherit
  an Astra parent identity. `VIBE_HARNESS_PROFILE=legacy` selects legacy workflow
  even for Astra; it does not undo shared correctness fixes.

## Shared changes

- Every Codex wrapper executes a task once. `CODEX_RETRY` and
  `CODEX_RETRY_DELAY` are ignored because failure may follow partial changes.
  Inspect state and use native retry/resume before a new execution.
- Windows child execution preserves UTF-8 and shell metacharacters without a
  second shell. A failed child retains its nonzero exit status. Explicit model
  and sandbox flags override defaults without duplicate arguments.
- Verification tracks actual script/document dependencies and nested integration
  tests, separates model profiles, rejects/repairs malformed success receipts and
  refuses receipts when inputs change during execution. Pro verification bases
  must be explicit; ambient `ACTIVE.json` is not a base authority.
- Verification executes and records each group independently. A later failure
  keeps valid earlier receipts, and later mutations invalidate earlier or reused
  inputs. Standalone test invocations clear Node's private test-context marker so
  a nested invocation cannot silently skip files and record false success.
- Static preflight audits reuse only passing results bound to their input contents.
  Current project state and environment checks always run. `--force-audits` bypasses
  cache reuse; unavailable cache storage falls back to executing audits.
- Sidecar/run-agent metadata distinguishes requested from unconfirmed effective
  model/effort. Model resolution and interview algorithms have one shared kernel.
- Pure protocol hash tests use file fixtures. Template hygiene checks the Git
  shipping set, including staged files, while preserving local user drafts.
  Historical milestone/ledger and source-function-placement assertions are removed;
  behavior, ownership, approval, migration and transport checks remain.
- CI includes an Astra suite and focused native Windows coverage.
- Concurrent dashboard tests validate the selected available port instead of
  assuming the adjacent port is free. Stop-hook fixture cleanup tolerates the
  brief Windows cwd lock between lease release and background process exit.
- Profile fixtures do not inherit live project state or unrelated project
  context. Statusline input handles delayed pipes while keeping a bounded wait
  for producers that never close their input.

## Upgrade and compatibility

No product migration is required. Run a dry-run before syncing the exact release:

```bash
npm run vibe:sync -- --ref v1.15.0 --dry-run
npm run vibe:sync -- --ref v1.15.0
```

Inspect local harness conflicts and preserve project-specific provider/agent
settings. Sync keeps product code/context, runtime state and `PROJECT:*` blocks.
The new short contract is harness-owned; no project model default is upgraded
solely because the registry lists Astra. Existing exact Pro ownership, append-only
evidence, approval and terminal-close rules remain intact.

## Verification and limits

Implementation verification passed legacy 575/576 (one conditional skip) and
Astra 566/568 (two conditional skips), with zero failures, plus build, schema,
structural audits, UTF-8 and context checkpoints. Full forced verification also
runs at the release boundary. UI implementation is unchanged from its passing
Chromium smoke checks.

The same-reference diagnostic reduced automatic injected text from 35,861 to
3,215 bytes. This is not total context, billing or task-quality evidence. A
12-case real-model comparison is prepared, but child runtime inspection was
reported as policy-blocked/read-only; task-success equivalence remains unverified.
