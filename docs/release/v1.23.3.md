# v1.23.3 - The Harness Closes Its Browser Reliably on Windows

Date: 2026-11-19

## What changed

- v1.23.2 said Stagehand 4.4.0 ended the Windows browser-close failures. It made them rare on a quiet
  machine and left them in place under load: with the suite's Git-heavy group running beside it, 11
  of 180 closes still failed, with `taskkill exited with code 255` and, in most of them, `EBUSY` on
  the profile's `lockfile`. Stagehand asks Chrome to exit over DevTools, waits 5 seconds, then runs
  `taskkill` against a process tree that is already ending and deletes the profile once while Chrome
  still holds it. Chrome does exit; `browser.close()` has rejected by then
  (browserbase/stagehand#3166, open).
- `openHeadlessPage()` in `.vibe/harness/scripts/lib/stagehand-browser.mjs` now closes through
  `closeLaunchedBrowser()`:
  - the Chrome profile is a directory the harness creates and passes as `userDataDir`, which Stagehand
    never deletes;
  - a rejected `browser.close()` counts as closed once the DevTools endpoint (`browser.cdpUrl`) stops
    accepting connections, and is rethrown if Chrome is still there after 10 seconds;
  - the profile is removed afterwards with retries (`maxRetries: 10`, `retryDelay: 100`).
- `vibe:test-ui` and `vibe:browser-smoke` use this helper, so both get the fix. The Stagehand
  test-pattern shard names the pitfall for project tests that launch a browser themselves.

## Downstream impact

- Sync replaces the helper and its test. No migration, schema or protocol change.
- The helper reads `browser.cdpUrl`, which Stagehand exposes from 4.4.0. With an older Stagehand a
  rejected close is rethrown as before; the profile is still the harness's own directory.
- A project that launches Stagehand itself (not through the helper) keeps Stagehand's behavior.

## Verification

- Same loop, same machine, same load (the `pro-roundtrip` test group running beside it), Stagehand
  4.4.0: helper of v1.23.2, 180 cycles, 11 close failures; this helper, 120 cycles, 0 close failures.
  One of those 120 cycles failed while opening the browser (Stagehand initialization timed out after
  60 s), a path this release does not change.
- Three unit tests drive the helper with a rejected close: endpoint gone (resolves, profile removed),
  endpoint still accepting (rethrows, profile kept) and a clean close. Three seeded bugs in the helper
  each fail one of them.
- `npm run vibe:test-ui` and full forced release verification: see the release commit.
