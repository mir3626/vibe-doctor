# v1.15.4 - Astra Role Execution and Prompt Alignment

Date: 2026-09-09

Astra Sprint completion no longer creates open Evaluator risks solely because an
audit counter reaches its threshold. Preflight and commit treat only the exact
historical automatically generated reminder as advisory. Counters and existing
records remain intact; actual findings, records with additional evidence and
legacy rollback keep their blocking behavior. No state migration is required.

Init delegation now lets the receiving session choose its own verified model
profile. The concise entry preserves initialization, scope and readiness checks;
lower/unknown models and explicit legacy overrides load the separate legacy
runbook. A parent's model does not establish a child's eligibility. Planner
handoffs distinguish confirmed contracts from recommended implementation details,
and Astra coder instructions allow routine decisions within the approved scope.

`vibe:run-agent --role planner|generator|evaluator` resolves the target checkout's
role configuration and registry model and connects it to the actual child
invocation. Role headers belong to that task's prompt. Explicit provider pins
remain authoritative; conflicting `--model` values fail before execution. Custom
runners declare their model transport with `{model}`. Template expansion happens
once, preserving literal placeholders and replacement metacharacters in task text.
Requested model information remains distinct from an unconfirmed effective model.

Root instructions and runtime notes now identify roles from the task rather than
treating the common Codex wrapper as Generator-only. Existing role defaults,
explicit write scope, initialization, encoding, workflow ownership and Pro
execution bindings remain unchanged. The legacy comparison path remains
`VIBE_HARNESS_PROFILE=legacy`; no live model performance improvement is claimed.

Use [the profile guide](../guides/astra-profile.md) for configuration and
compatibility details. Downstream upgrades should use the normal sync dry-run and
preserve local role/provider overrides. This release does not start product work,
resume a Pro flow or perform a downstream upgrade automatically.
